Why Solana first.

Every Solana transaction is authorized with Ed25519. Wallets, program upgrade authorities and validator keys all depend on a scheme that Shor's algorithm breaks on a large enough quantum computer.

Vantax cannot change Solana's base signatures. It works as a layer around them, and this part is in progress: scanner rules for Solana codebases, PQ-signed attestations and audit trails that sit next to programs, and guidance on hybrid verification.

Twelve crates. Each answers one question.

A flaw in one component never carries the authority of another. The scanner never holds a signing key, so it has none to leak.

Rules the code enforces.

Each of these is refused in code, not left to configuration.

  • No signing oracle.The gateway signs only its own attestations, from a closed set, under a fixed domain tag. Customer keys stay with the customer.
  • A valid signature is not authority.Verification and authorization are separate checks. Revoking an issuer revokes everything it signed.
  • Humans own irreversible decisions.Sentinel suspends automatically. Revocation always escalates to a person, and protected identities are never contained automatically.
  • A threshold of one is refused.Bridge signers are counted by distinct fingerprint, and the circuit breaker never resets itself.
  • History survives rotation.Keys resolve by timestamp, so old signatures still verify. The audit log is hash-chained, so editing one entry breaks every entry after it.
