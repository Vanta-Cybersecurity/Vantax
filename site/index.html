Why Solana first.

        
Every Solana transaction is authorised with Ed25519. Wallets, upgrade authorities and validator keys all rest on a scheme that Shor's algorithm breaks on a large enough quantum computer.

        
Your address is your public key, so it is already public, on-chain, forever. Nobody can run Shor at that size today, but anyone can collect keys now and wait.

        
Vantax cannot change Solana's base signatures, and doesn't claim to. It works around them: it finds where your code depends on Ed25519, binds a post-quantum key to the account, and refuses actions that arrive without the post-quantum signature. Solana's own teams have picked Falcon-512 for the protocol itself; Vantax supports it today.

Rules the code enforces.

        
Each of these is refused in code, not left to configuration.

      

      
    
        
  • No signing oracle.The gateway signs only its own attestations, from a closed set, under a fixed domain tag. Customer keys stay with the customer.
    • 
        
  • A valid signature is not authority.Verification and authorisation are separate checks. Revoking an issuer revokes everything it signed.
    • 
        
  • Humans own irreversible decisions.Sentinel suspends automatically. Revocation always goes to a person, and protected identities are never contained automatically.
    • 
        
  • A threshold of one is refused.Bridge signers are counted by distinct fingerprint, and the circuit breaker never resets itself.
    • 
        
  • History survives rotation.Keys resolve by timestamp, so old signatures still verify. Editing one audit entry breaks every entry after it.
    • 
        
  • The scanner holds no keys.It only reads code, so it has nothing to leak and nothing to sign with.
